# 知识库 Agent 设计说明

> 文档类型：MVP 产品与技术设计说明  |  版本：v1.0  |  日期：2026-08-02

> 目标：让知识库 Agent 基于结构化需求与选品结果，只调用真实存在、可用且适配当前任务的资产；当数量或类型不足时，明确进入人工决策分支，不虚构资产。

## 1. 定位与边界

知识库 Agent 位于需求理解 Agent、选品 Agent 与创意方案/生成 Agent 之间。它不负责生成最终图片或视频，也不替代知识资产的运营管理；它负责把“本次生成需要什么资产”转换成可追溯的资产调用快照。

标准链路为：意图理解 → 资产召回 → 资产过滤 → 资产排序 → 数量和类型校验 → 输出资产或反馈缺失。

### 1.1 输入

| 输入方 | 输入内容 | MVP 使用字段 |
|---|---|---|
| 需求理解 Agent | 结构化需求快照 | 生成形式、渠道、品牌、版位比例、风格标签、商品类目 |
| 选品 Agent | 已排序且经运营确认的商品 | 商品 ID、商品名称、类目、Top10/Top20 清单 |

### 1.2 输出

| 输出对象 | 正常分支 | 异常分支 |
|---|---|---|
| 任务编排 Agent | 资产调用清单、版本、推荐分、评分拆解、覆盖校验结果 | 缺失资产类型、缺失数量、缺失原因、运营决策结果 |
| 创意方案/生成 Agent | 冻结后的资产快照 | 运营确认“接受缺口”或“调整方案”后的新快照 |

## 2. 资产分类

### 2.1 公共资产

| 资产类型 | 作用 | 图片任务 | 视频任务 |
|---|---|---|---|
| 品牌 Logo（brand_logo） | 品牌识别、标准色和安全区 | 必需 | 必需 |
| 字体（font） | 标题、正文、数字和价格表达 | 必需 | 可由字幕模板内置，MVP 图片必需 |

### 2.2 图片资产

| 资产类型 | 作用 | 默认数量 |
|---|---|---|
| 商品图（product_image） | 商品主体、细节、角度和白底图 | 1 |

| 图片版式模板（image_layout） | 商品、文案、Logo 与 CTA 的版式及安全区 | 1 |

### 2.3 视频资产

| 资产类型 | 作用 | 默认数量 |
|---|---|---|
| 商品图（product_image） | 商品主体、细节与画中画素材 | 1 |
| 视频模板（video_template） | Hook、场景、利益点、CTA 的镜头结构 | 1 |
| 数字人（digital_human） | 产品讲解、场景种草、权益说明 | 3 |

| 背景音乐（bgm） | 节奏、情绪与转场承接 | 1 |

## 4. 召回规则

### 4.1 生成形式路由

图片任务仅召回 product_image、background_image、brand_logo、font、image_layout；视频任务仅召回 product_image、video_template、digital_human、video_background、subtitle_style、brand_logo、bgm。未被当前任务需要的类型不进入候选集。

### 4.2 召回键

1. 以资产类型为第一层硬路由。
2. 以商品 ID 和商品类目召回商品专属或类目相关资产。
3. 以渠道、版位比例、品牌范围和风格标签扩展候选。
4. 通用资产使用 all 或空商品绑定召回，但排序优先级低于精确匹配资产。

### 4.3 召回结果约束

召回结果必须保留召回原因、来源文件和版本。MVP 为本地 JSON；正式版本可替换为向量检索、标签倒排或混合检索，但输出契约不变。

## 5. 过滤规则

过滤采用“单资产单主因”计数，按以下优先级执行，便于漏斗统计和问题定位。

| 优先级 | 规则 | 判定 | 处理 |
|---|---|---|---|
| 1 | 已失效 | status = expired | 直接淘汰 |
| 2 | 已下架 | status = unlisted | 直接淘汰 |
| 3 | 重复资产 | duplicateOf 非空或校验和重复 | 保留原资产，淘汰副本 |
| 4 | 文件损坏 | fileHealthy = false、空文件或校验失败 | 直接淘汰并告警 |
| 5 | 清晰度不足 | quality.resolution < 70 | 淘汰，允许运营补充高质量版本 |
| 6 | 版权不可用 | license.status ≠ available | 直接淘汰，不允许静默降级 |
| 7 | 品牌不适用 | brandScopes 不含当前品牌或 all | 淘汰 |
| 8 | 渠道不适用 | channels 不含当前渠道或 all | 淘汰 |
| 9 | 尺寸不适用 | aspectRatios 不含当前比例或 all | 淘汰 |

正式版本还应将授权地域和到期时间加入实时校验，并把文件损坏、版权失效等治理问题写回知识库运营队列。

## 6. 排序规则

过滤后的资产在各自类型内部排序，不允许用高分背景替代缺失数字人。MVP 综合分如下：

综合推荐分 = 需求匹配 × 30% + 商品匹配 × 25% + 渠道匹配 × 20% + 风格匹配 × 15% + 质量分 × 10%。

| 维度 | 计算重点 | 说明 |
|---|---|---|
| 需求匹配 | 类目与结构化需求 | 精确类目优先于通用资产 |
| 商品匹配 | 商品 ID、商品类目 | 商品专属资产优先于无绑定资产 |
| 渠道匹配 | 当前渠道 | 精确渠道优先于 all |
| 风格匹配 | tags 与 styleTags 交集比例 | 真实、轻促销、数码等标签 |
| 质量分 | resolution 与 completeness 均值 | 只对通过硬过滤的资产排序 |

同分时按 assetId 升序保证结果稳定。后续可加入运营确认率、生成成功率、投放 CTR/CVR 和素材审核通过率作为回流特征，并按渠道或人群动态调权。

## 7. 数量和类型校验

知识库 Agent 按“创意方案需要数量”与“过滤后可用数量”逐类型比对。每类资产输出 required、available、selected 和 ready/missing 状态。

图片 MVP 默认需要 5 类资产各 1 个。视频 MVP 默认需要 1 个商品图、1 个视频模板、3 个数字人、1 个视频背景、1 个字幕样式、1 个品牌 Logo 和 1 个 BGM。数字人需要覆盖产品讲解、场景种草和权益说明三个方向；即使现有两个数字人综合分很高，也不能将 2/3 判定为齐全。

## 8. 缺失资产处理

### 8.1 反馈契约

每个缺口必须包含：资产类型、要求数量、可用数量、缺失数量、缺失原因、可选动作。知识库 Agent 状态置为 needs_decision，并把结果交给任务编排 Agent。

### 8.2 运营决策

1. 补充相应资产：打开资产补充入口，新增后重新执行过滤、排序与校验。
2. 补充数字人：针对数字人缺口进入专用补充入口。
3. 不补充，继续生产：记录“接受缺口”的人工决策和风险，不伪造资产。
4. 调整当前创意方案：降低数量、删除资产类型或切换表达方式，然后重新校验。

MVP 的补充资产写入本任务临时资产集；正式版本必须进入知识库审核、授权、版本和发布流程。所有决策应记录操作者、时间、原缺口、最终方案和资产快照版本。

## 11. MVP 验收标准

1. 图片任务不会召回视频模板、数字人、BGM 等无关资产；视频任务不会召回图片背景和图片版式。
2. 九类过滤原因均可计数，并且被过滤资产不能进入排序和最终调用清单。
3. 各资产类型独立排序，结果可查看五维评分拆解。
4. 图片样例链路可得到完整资产清单；视频样例链路必须识别数字人 2/3 缺口。
5. 运营可补充资产、补充数字人、接受缺口继续或调整方案，操作后得到明确状态。
6. 最终调用清单包含资产 ID、版本、推荐分和输入需求/商品快照，可供任务编排和生成阶段追溯。

## 12. 后续演进

短期接入知识库新增/审核/发布流程与真实对象存储；中期引入向量与标签混合召回、授权到期任务、生成成功率和人工确认结果；长期引入投放数据回流、按渠道/人群动态调权及资产自动淘汰策略。
